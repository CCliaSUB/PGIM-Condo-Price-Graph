# Reproducing the pipeline

Everything below runs from the repository root. A CUDA GPU is required for training
and evaluation (tested on RTX 3090s, 24 GB). Timings are for one GPU.

```
data/raw/*.csv ──1──► data/processed/<dataset>_<task>/ ──2──► graph context ──3──► checkpoints/ ──4──► predictions
               build node tables                     (edges built          train            evaluate / demo
                                                       on first load)
```

## 0. Environment

```bash
pip install torch==2.4.0 --index-url https://download.pytorch.org/whl/cu124
pip install -r requirements.txt
unzip pgim_condo_graph_data.zip      # data/raw, data/processed, demo/predictions
```

The data package already contains the processed tables, so steps 1 and 2 are only
needed to rebuild from the raw panels.

## 1. Node tables from the raw panels (~1–3 minutes each)

```bash
python pipeline/build_database.py --config src/config/graph/rent.yaml \
    --input data/raw/ccr_rent.csv --output data/processed/ccr_rent
python pipeline/build_database.py --config src/config/graph/sale.yaml \
    --input data/raw/ccr_sale.csv --output data/processed/ccr_sale
python pipeline/build_database.py --config src/config/graph/rent.yaml \
    --input data/raw/full_sg_rent.csv --output data/processed/full_sg_rent --allow-missing-locations
python pipeline/build_database.py --config src/config/graph/sale.yaml \
    --input data/raw/full_sg_sale.csv --output data/processed/full_sg_sale --allow-missing-locations
```

`--allow-missing-locations` keeps the Full SG projects that have no coordinates
instead of stopping. The output matches the delivered `data/processed` tables byte
for byte.

Static relation tables (`edges/*.csv`) are generated by the data loader the first
time a configuration that uses them is loaded, and reused afterwards. Dynamic
relations (same-MRT with opening dates, price-peer) are rebuilt in memory every run.

## 2–3. CCR models

One run trains one model for a target, horizon and relation set, and saves the
best-validation checkpoint:

```bash
python pipeline/ccr_study.py --dataset ccr --task rent --horizon 12 \
    --edge-subset same_mrt,similar_price --gpu 0 --evaluate-test
# -> runs/ccr_study/edge_screen/<run name>/best_validation.pt, result.json
```

`--edge-subset` takes any combination of `adjacent_mrt, dist, same_mrt,
same_mrt_dist, same_school_dist, similar_price` (size-project is always included), or
`none` for size-project only. The delivered models used:

| Model | `--edge-subset` |
|---|---|
| rent h1 | `same_mrt` |
| rent h12 | `same_mrt,similar_price` |
| rent h24 | `none` |
| sale h1 | `dist,similar_price` |
| sale h12 | `dist,same_school_dist` |
| sale h24 | `adjacent_mrt,dist,same_mrt,same_mrt_dist,same_school_dist` |

They were selected by running all 64 subsets for each target and horizon and taking
the lowest validation RMSE; the full screen is in
`results/ccr/relation_subset_screen.csv` and the ranking across settings in
`results/ccr/relation_subset_ranking.csv`. A run takes 1–4 minutes.

To package a run as a delivered checkpoint, copy `best_validation.pt` to
`checkpoints/ccr/<task>_h<h>/model.pt` and update `meta.json`.

## 2–3. Full SG models

Full SG precomputes the graph context once per task into a cache (about 5 GB for rent
and 6 GB for sale), then trains from it.

```bash
export BENCH_CACHE=/fast/disk/full_sg_cache        # default: results/full_sg/cache
python benchmark/build_cache.py --task rent --gpu 0   # ~2-3 minutes
python benchmark/build_cache.py --task sale --gpu 0   # ~4-5 minutes
```

The cache also contains `graph_snapshots.csv.gz`, the monthly same-MRT, price-peer and
size-project links used by the map demo.

Training reads the validation results of the configuration search from
`results/full_sg/search/` and trains the best configuration:

```bash
python benchmark/train_nn.py --task rent --graph hetero --temporal transformer \
    --phase final --seeds 42 --gpu 0
python benchmark/train_nn.py --task sale --graph hetero --temporal transformer \
    --phase final --seeds 42 --horizons 1 12 --gpu 0
python benchmark/train_nn.py --task sale --graph hetero --temporal gru \
    --phase final --seeds 42 --horizons 24 --gpu 0
# -> results/full_sg/final/<task>/hetero_<temporal>/model_h<h>_s42.pt, pred_*.parquet, results.jsonl
```

The temporal module per setting is the validation choice recorded in
`results/full_sg/summary/validation_choice.json` (`*_hetero` keys). To rerun the
search itself, use `--phase search` (optionally `--target logratio`) for each
temporal module; it writes the same `results/full_sg/search/` files.

Each run takes 2–12 minutes. GPU training is not bit-reproducible, so a retrain gives
slightly different weights and metrics (see [checkpoints.md](checkpoints.md)).

## 4. Evaluation and demo predictions

```bash
python scripts/evaluate_checkpoints.py --dataset full_sg --task sale --horizon 24 --gpu 0 --demo
```

prints test metrics next to the values in `meta.json`, and with `--demo` writes
`demo/predictions/full_sg_sale_h24.csv`. For Full SG, copy the cache's
`graph_snapshots.csv.gz` to `demo/predictions/full_sg_<task>_graph_snapshots.csv.gz`.

## Verification done for this delivery

- All 12 checkpoints were scored from this repository and the renamed data; every
  test RMSE and sample count matched `meta.json` exactly.
- The Full SG cache rebuilt from `data/processed` gave identical predictions, and its
  graph snapshots were identical to the demo's files.
- Node tables rebuilt from the raw panels with the step 1 commands were
  byte-identical to `data/processed` for `ccr_rent`, `full_sg_rent` and `full_sg_sale`
  (`ccr_sale` was not rerun). For `ccr_rent`, all six static edge tables generated by
  the loader were byte-identical as well.
- The demo's 51 backend tests pass against the four delivered datasets.
